# AI 续写小说工作流报告

更新时间：2026-05-22

## 你的核心工作流

1. 导入小说或新建小说
2. 进入小说编辑器 / 工作台继续写作
3. 调用 AI 模型按用户需求续写
4. 当前文过长时，先做剧情概要提炼
5. 将提炼结果放进缓存库，再人工筛选
6. 合格内容转入剧情库
7. 之后再把剧情库内容回喂给 AI，减少 token 浪费并保持上下文一致

## 针对你业务目标的判断

你的产品核心不是“把所有页面做花”，而是把这条链做稳：

`导入小说 / 新建小说 -> 工作台续写 -> 剧情概要提炼 -> 缓存库筛选 -> 转入剧情库 -> 回喂 AI`

这条链直接决定：

- token 是否浪费
- AI 是否和前文脱节
- 长篇续写是否稳定

## 关键建议

### 1. 继续强化“提炼剧情 -> 缓存库 -> 剧情库 -> AI回喂”

这是最接近你业务价值核心的一条链。建议继续加强：

- 缓存库单条转正
- 缓存库批量转正
- 缓存结果删除 / 清理
- 剧情库筛选后的精准回喂

### 2. 工作台右侧 AI 助手继续和剧情库打通

理想状态是：

- 自动携带当前章节正文
- 自动携带已沉淀的剧情概要
- 再拼接用户即时需求

这样续写才真正稳定。

### 3. 智能导入必须做真实样本回归

编译通过不代表导入稳定。真实小说文本的章节标题、空行、简介、卷结构差异很大，必须拿真实样本反复测。

### 4. 剧情库最好继续补“半人工筛选”能力

你现在已经有缓存库转正式剧情库的链路。下一步最实用的是：

- 勾选若干条
- 批量转正
- 删除不合格缓存

这会更像真正的编辑审核流。

## 当前建议的后续优先级

1. 小说编辑器 / 工作台继续向旧版 1:1 贴合
2. 提炼剧情继续压细节
3. 缓存库增加单条 / 多条转正
4. 智能导入做真实样本文本回归
5. 最后再做一轮完整逐页验收
